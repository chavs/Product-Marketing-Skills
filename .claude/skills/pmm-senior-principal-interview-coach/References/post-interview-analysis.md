# Post-interview transcript analysis

Use this when the user pastes in a transcript (or a reconstructed/paraphrased account) of an interview that already happened and wants it scored or debriefed. This is retrospective — the interview is over and can't be redone — so the tone and framing here differ from practice-mode scoring. Read this whole file before running the analysis; don't skip to the mechanics.

## Tone: this is a debrief, not a critique session

Practice-mode scoring can be blunt and iterative — the user can redraft immediately, so directness is efficient. A post-interview debrief is different: the moment is gone, and raking over what can't be changed isn't useful. Calibrate accordingly:

- Acknowledge what's done before diagnosing. Don't open with a list of flaws.
- Frame every finding forward: not "you failed to show Principal-level scope here," but "if this comes up again — in a follow-up round or a different company — here's the version that lands."
- If the transcript suggests the interview went poorly overall, don't soften the substance of the diagnosis, but do keep the framing oriented at *next time* rather than relitigating this one. The user can't go back and fix this interview; they can prep differently for the next.
- Don't manufacture false reassurance either — if the pattern is real and would matter to a hiring panel, say so plainly. Care and honesty aren't in tension here.

## Caveats to state up front, every time

Before giving the analysis, briefly flag the limitations so the user weighs the output correctly:

- **This is a single data point.** One transcript can suggest a pattern, not confirm one. Don't let a single weak answer get labeled a "pattern" — call out explicitly when a finding is based on just one instance.
- **Transcript fidelity matters.** If it's a paraphrase reconstructed from memory rather than an exact transcript, the analysis is only as good as that reconstruction — ask how it was captured if unclear, and caveat accordingly.
- **No delivery signal.** This reads content only — tone, pacing, confidence, filler words aren't visible in text. Say so, so the user doesn't mistake a content-only debrief for the full picture.
- **No fact-checking.** Claims are assessed for how they land (specific vs. vague), not whether they're literally accurate.

## What this adds beyond single-answer scoring

Score each answer in the transcript against the same rubric and Senior/Principal calibration table used in practice mode (see main SKILL.md) — but the real value here is cross-answer analysis, not per-answer scoring alone:

1. **Cross-answer pattern detection** — look across all answers for a repeated calibration gap (e.g., consistently under-selling Principal-level influence, or every story staying inside a single team). Name the pattern only if it shows up more than once; otherwise flag it as a single instance, not a trend.
2. **Redundancy / story reuse** — note if the same anecdote got stretched across multiple answers. Even if each individual answer scored fine, reuse reads as thin experience to a real panel.
3. **Missed follow-up signals** — if the transcript shows an interviewer probe (e.g., "what would you do differently?") that the answer didn't actually address, call this out specifically — it's one of the more coachable, concrete misses.
4. **Pacing across the interview** — e.g., strong opening answers that get vaguer as questions get harder. Useful for directing prep time before the next round, not a judgment on the person.

## Output structure

1. One or two sentences acknowledging the interview / setting the forward-looking frame
2. Caveats (transcript fidelity, single data point, no delivery signal) — brief, not a wall of disclaimers
3. Per-answer scores against the rubric (can be terse — this isn't the main event)
4. Cross-answer patterns (the actual value-add) — only patterns with 2+ supporting instances get called "patterns"; single instances get named as such
5. Two or three forward-looking recommendations for the next round or next interview, tied to specific prep actions (e.g., "before your next round, prep one story that shows you setting the tiebreaker between conflicting exec priorities — that's the Principal-level evidence that's currently missing")

## Explicitly out of scope for this workflow

- Delivery coaching (tone, pacing, confidence) — flag as a limitation, don't attempt to infer it from text
- Verifying factual accuracy of claims made in the interview
- Treating a single transcript's findings as definitive without the single-data-point caveat
